# ลำดับพัฒนา

ทุก milestone ด้านล่างยังไม่เริ่ม เอกสารนี้เป็นแผน ไม่ใช่หลักฐานว่าแอปทำงานแล้ว

| ขั้น | สิ่งที่จะทำ | เกณฑ์ผ่าน |
| --- | --- | --- |
| M1 — เปิดแอปได้ | Android project, Home → Running → Summary, ข้อมูลจำลอง | Build และติดตั้งบนมือถือจริงได้ กด Start / Stop และกลับ Home ได้ |
| M2 — บันทึกจริง | GPS + Room + location foreground service + History | เดินกลางแจ้ง 5–10 นาที จุดถูกเขียนระหว่างเดิน ปิดจอและสลับแอปแล้วกลับมาตรวจได้ Stop แล้วเปิดแอปใหม่ยังเห็น session |
| M3 — รับมือการขาดช่วง | ตรวจ recorder และ session ค้าง แสดง GPS loss / interrupted | ทดสอบ process death และ Force stop แยกกัน จุดที่เขียนแล้วคงอยู่ ไม่แสดงว่าบันทึกต่อเนื่องทั้งที่หยุดไป |
| M4 — ตัวเลขตรวจสอบได้ | Distance, elapsed time, average pace | Unit test ด้วย fixture ที่รู้ผล รองรับจุดซ้ำ ไม่มีจุด เวลาไม่ถูกต้อง และ GPS gap โดยไม่คำนวณข้าม segment |
| M5 — ภาพผลวิ่ง | Route geometry, ภาพ 9:16, PNG, Android Share | แชร์ภาพได้จริง ตัวเลขตรงกับ summary ตรวจ preview และการซ่อนจุดเริ่ม/จบก่อนแชร์ |
| M6 — ใช้ต่อเนื่อง | ทดลองวิ่งจริง 10–20 ครั้ง ปรับ GPS filtering และ battery | มีบันทึกผลจริง ระบุปัญหาที่พบและข้อจำกัด ยังไม่อ้างว่าเชื่อถือได้ทุกอุปกรณ์ |

M2 มี persistence และการทำงานตอนปิดจอตั้งแต่แรก ส่วน M3 ทำให้การขัดข้องตรวจพบและอธิบายได้
ไม่รอให้วิ่ง 10–20 ครั้งแล้วค่อยเพิ่มการบันทึกลงเครื่องหรือ foreground service

## งานแรกสำหรับการเขียน code

สร้าง M1 เท่านั้น: app module เดียว ใช้ Kotlin + Compose มี Home, Running และ Summary
Start เปิด Running พร้อม timer จำลอง Stop ไป Summary โดยระบุว่าข้อมูลเป็น demo
ยังไม่ต่อ GPS หรือ Room ในงานนี้
ส่งงานพร้อมผล build, วิธีติดตั้งและผลทดสอบบนมือถือ ถ้ายังไม่มีมือถือให้ระบุว่าทดสอบได้ถึง emulator เท่านั้น

## วิธีปิดแต่ละงาน

- ระบุสิ่งที่เปลี่ยนและทำไม
- อธิบาย input, output และเจ้าของ state ของระบบที่เพิ่ม
- แนบผลทดสอบพร้อมชนิดหลักฐาน: unit test / emulator / มือถือจริง
- บันทึกข้อจำกัดและงานถัดไป ไม่ทำเครื่องหมายผ่านแทนผู้ใช้ใน test ที่ยังไม่ได้ทำ
